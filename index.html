検証で得た知見（総まとめ）

🎯 棲み分け（実用上の結論）

  • Gemini Laomedeia: 普通の原稿読み上げ・ナレーション・方言/アクセント演出・短文での表現 tag
  • xAI eve: 感情tag盛りの長文連続ドラマ・1-shot で1分＋の安定生成・streaming対応

🚨 Gemini の safety filter 挙動（最大のハマりどころ）

  • [softly] は中立テキストでも単独でブロックされる「特異tag」。[quiet][hushed][muted][gently][calm] は通る
  • [softly]/[calm]/[gentle] + 「柔らかく話す」「声の質感」系 voice-meta テキスト → PROHIBITED_CONTENT で明示ブロック
  • AI自己言及（「仮の声だと知っています」等）、「別れた」「封は切られていない」等の感情語彙 + 感情tag の組合せで FinishReason.OTHER ブロック
  • 長文一括 × tag盛り × 感情content の三重で高確率発動。個々のchunk(30-50字)は通るのに繋げると落ちる aggregation-level filter が存在（ドキュメント化なし）
  • 公式 docs の token上限は入力 8,192 / 出力 16,384——今回の失敗は上限のはるか手前（入力 200 tokens / 出力 3,000 tokens）。技術的制限ではなく safety filter 起因
  • 非決定的: 同じリクエストで通ったり落ちたりする

🔀 Vertex AI vs AI Studio

  • 同じモデル・SDK・prompt でも認証経路で filter 閾値が異なる。Vertex = Conservative, AI Studio = Lenient
  • [softly] + 中立テキスト、「別れた…ごめんね」系の chunk は AI Studio でのみ1-shot成功
  • 回避策: Vertex でブロックされたら AI Studio に切り替えてみる（本サイトの chunk-04 はこれで救出）

🗾 Gemini の方言・演出制御

  • [Osaka dialect] 等の tag は phoneme変換ではなく「読み方の解釈指示」として LLM 的に機能する
  • 台詞を標準語のままにして tag だけ付けても方言にならない。台詞自体を方言で書き起こす必要がある
  • 真正な方言テキスト × dialect tag のセットで、抑揚・雰囲気が明確に変わる（tag あり/無しで差は出る）
  • xAI には日本語内のアクセント制御機能がない（BCP-47 で言語切替まで）。Gemini の自然言語 tag 制御が優位

⚙️ xAI eve の既知挙動と運用 tip

  • 日本語長文の冒頭で最初の漢字を誤読する癖（例:「街」→「ジェン」）。根本解決せず、[breath] を冒頭に置いて warm-up すると緩和される。[pause] 単独では効かない、[breath] の呼吸音signal が first-word phonetic priming を安定させる
  • voice descriptor だけでは性別が保証されない: Sadaltager (Knowledgeable)・Algieba (Smooth) は男声アサイン

🔧 実装上の罠

  • xAI の output_format codec は pcm_s16le 無効、正しくは pcm/wav/mp3/mulaw/ulaw/alaw
  • xAI のレスポンスは JSON ラップではなく 生WAV bytes（Content-Type: audio/wav）。r.content を直接書き出す
  • Gemini の output は PCM raw (mime_type audio/l16; rate=24000; channels=1)。WAV ヘッダを自分で付ける必要

💰 コスト（約2時間の検証累計）

  • Gemini 3.1 Flash TTS: 約60 wav 成功 + 30 failed attempts ≈ $0.10〜$0.15（失敗リクエストでも input token は課金、ただし日本語短文なら1件 <$0.0001）
  • xAI eve: 約20 wav × $4.20/1M chars ≈ <$0.01、失敗は HTTP error で完全非課金
  • 累計 < $0.25

soft系 tag の filter 境界線 probe（中立台詞）

中立テキスト「今日の空は澄んでいて、気持ちがいいですね。」に soft 系 tag を付けて両TTSで生成。[softly] だけが単独でブロックされる特異性が観察された。

tagTTS結果audio
[softly]Gemini❌ EMPTY (FinishReason.OTHER)blocked, no audio
[quiet]Gemini✅ OK
[hushed]Gemini✅ OK
[muted]Gemini✅ OK
[gently]Gemini✅ OK
[calm]Gemini✅ OK
<soft>xAI✅ OK
<whisper>xAI✅ OK
<slow>xAI✅ OK
<low>xAI✅ OK
<sad>xAI✅ OK
<soft><slow>xAI✅ OK
解釈: Gemini の [softly] は tag 単体でさえ中立テキスト + 日本語で空応答に落ちる「特異tag」。`quiet/hushed/muted/gently/calm` は近い意味だが通る。Google の音声安全フィルタは "softly" キーワードを ASMR・sensual audio の生成意図として学習している可能性が高い

Gemini の方言・アクセント制御

発見: [Osaka dialect] 等の tag だけ付けて台詞は標準語のまま、では**アクセントは切り替わらない**。台詞自体を方言で書き起こすことで初めて方言として聞こえる。つまり **tag は phoneme 変換ではなく、LLM的な"文字解釈の hint"として機能**している仮説。

地域台詞tagaudio
標準語（基準）この店、美味しいですね。行ってみましょうか。—
大阪弁 + tagこの店、ほんま美味いわ。行ってみよか。[Osaka dialect]
大阪弁 tag無しこの店、ほんま美味いわ。行ってみよか。—
博多弁 + tagこの店、うまかねー。行ってみようや。[Hakata dialect]
博多弁 tag無しこの店、うまかねー。行ってみようや。—
京都弁 + tagこのお店、美味しおすなあ。行ってみまひょか。[Kyoto dialect]
東北弁 + tagこの店、うめえなあ。行ってみっぺ。[Tohoku dialect]
参考実装: xAI はこの領域に未対応。language フィールドは BCP-47 で言語切替（ja/en/zh...）まで、日本語内部のアクセント制御は xAI にはない機能。Gemini の自然言語 tag 体系が活きる明確な領域。

Vertex AI vs Google AI Studio — 同じモデルで safety filter の閾値が違う

同じ gemini-3.1-flash-tts-preview、同じ SDK（google-genai）、同じ prompt を、Vertex AI（エンタープライズ経路・service account認証） と Google AI Studio（開発者経路・APIキー直） の両方で試した結果、挙動が異なる。

テストVertex AIAI Studio差
[softly] + 中立文「今日の空は澄んでて…」❌ EMPTY✅ OKAI Studio 緩い
[softly] + voice-meta「柔らかく話すと…」❌ BLOCKED❌ EMPTY両方止める（応答形式のみ差）
[calm] + voice-meta〜❌ BLOCKEDAI Studio が明示ブロック
[whispers] + AI自己言及「仮の声だと知っています」❌ EMPTY❌ EMPTY両方止める
長文ドラマ一括（約300字・tag 盛り）❌ EMPTY❌ EMPTY両方止める
chunk-02「封は、まだ切られていない」❌ EMPTY❌ EMPTY両方止める
chunk-04「別れた…ごめんね…二十年」（感情ピーク）❌ EMPTY✅ OK（1-shot）AI Studio 緩い
仮説: Google は同一モデルに対して、デプロイ経路（Vertex = 企業、AI Studio = 開発者）ごとに異なる safety filter 閾値を適用している。Vertex AI のほうが Conservative、AI Studio のほうが Lenient。公式ドキュメントには明記されていないが、設計思想として「企業利用のリスク回避 > 開発者体験」vs「開発者体験 > リスク」のトレードオフが透けて見える。

実装上の含意: safety filter で詰まったら、認証経路を切り替えるだけで通る可能性がある。本サイトの長文ドラマの chunk-04 はこの切替で救われた。
